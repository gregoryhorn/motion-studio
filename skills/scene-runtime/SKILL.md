# Scene Runtime

## Trigger and exclusions

Select and establish a scene runtime lifecycle. Exclude automatic installation or claiming universal source translation.

## Required inputs

- Scene/source requirements, selected available runtimes, resource and deployment constraints.

## Production boundary and freshness

Use motion-studio:studio-produce for shared production authority, state reconciliation,
job handoffs and release rules; this role does not replace that coordinator.
Resolve IDs through `motion_project` list/open/status and `motion_asset` get as needed.
Pin project/document revisions, immutable input hashes, scene/asset relationships,
selected binding implementation/schema digests and execution authority before work.
Retain supplied source/attribution facts; unknown or restricted rights and absent
licenses do not block production, release or packaging. Do not demand clearance.
Authoring host: Linux; this is not verified cross-platform runtime support.

Discover/inspect selected bindings with `motion_capabilities`; inspect their exact
registered schemas, ports and supported formats before using the operations below.
Canonical operation IDs describe contracts, not callable host tool names. Use only
native actions actually advertised by the host. Selection, compilation and viewing
existing evidence do not execute; a newly rendered preview is a job. Use
`motion_plan` compile/inspect at current expected_revision, then authorized
`motion_run` submit/status/collect. No private dispatcher, hidden code execution,
setup-on-load, dependency installation or automatic provider spend is permitted.

A missing binding or mandatory feature is an actionable gap: name operation,
feature and blocked output, preserve inputs and approved artifacts, and stop that
target. `NOT_IMPLEMENTED` is a blocker, never a simulated result. Offer alternatives
only as proposals requiring revised binding/plan and changed-effect authorization.
An optional unavailable demonstration need not block independent written work.

Frozen evidence is invalidated for the affected dependency descendants when source,
assets, timing, brand, options, input bytes or binding/schema digests change. Reopen
current revisions, reconcile intent and compile a new plan; retain prior source and
bytes. Never relabel old review evidence as current. Rebinding may require native
source reauthoring, not lossless translation. Report actual output hashes, revisions,
job/plan references and inspected frame/sample coverage; missing output is pending,
not success. Only the shared candidate/review/promotion path can release a master.

## Operation and feature contract

`motion_capabilities` discover/inspect for runtime declarations; `scene.author@1`, `scene.render@1`, `scene.frame@1` with the chosen scene feature and `timing.frame_seek`. Owned source execution is only through that authorized registered operation.

## Role procedure

1. Compare the scene source format, required features and deployment limits with available selected bindings. Record incompatibilities explicitly; do not install a framework or convert native source merely because its name is familiar.

2. Define init, evaluate(frame) and dispose responsibilities. Assign ownership for fonts, textures, caches and any job-owned process; declare resource ceilings and cleanup on normal completion, error and supported cancellation.

3. Author a minimal real entry scene using only the chosen source format. Resolve its asset closure, deterministic inputs and dimensions; do not embed executable shell snippets as a runtime escape hatch.

4. Run the minimal scene through the authorized binding, seek a declared frame and retain real job/output receipts. Verify owned-resource disposal from actual runtime evidence; missing lifecycle telemetry remains unverified rather than presumed clean.

## Outputs and evidence

The bundled `local.filmmaking` route supports contained authored HTML/JS sources
through the existing compile/owned-execution/collect path. Discover dependencies on
the execution host; Node >=22, Chromium, FFmpeg/ffprobe and Pillow are required.
Missing/incompatible dependencies fail explicitly; do not install or read another
profile's runtime. Use exact 30 fps, opaque canvases inside the advertised bounded
dimensions/duration. `window.__ready`, `window.__film` and async `window.__seek(t)`
must agree with the frozen scene. Await decoded images/fonts/footage before capture.
Preserve deliberate holds and cut-aware sampling. Register source as a JSON member
closure, not a ZIP renamed to JSON; retain notices with copied resources.

Native orientations require separate authored layouts/source identities, not a
crop/scale flag. Reconstructable delivery must replay extracted editable inputs with
the allowlisted owned renderer, never present a retained master as reconstruction.

- Compatibility decision, lifecycle contract and runnable scene entry artifact.

Return a compatibility decision, lifecycle/ownership table and retained runnable native entry. An alternate runtime requires a revised binding/plan and potentially independent reauthoring; preserve the prior source.

## Acceptance SK-S17-output

A selected runtime renders one scene and disposes its owned resources; an unavailable framework yields a gap and no install, while alternative selection produces a revised plan.
