# Vector animation

## When to use

Author and export compatible vector animation. Exclude promising arbitrary effects in every vector player.

## Inputs and retained outputs

Required: Vector content, duration, target format/player/version and feature constraints.

Produce: Editable vector source, exported animation, actual player preview and compatibility receipt. Attach each output to its current
project and applicable scene/asset revision; retain editable source and actual
bytes, not only a screenshot, URL or completion message.

## Authority and execution boundary

Follow the shared production instructions in `motion-studio:studio-produce`
before this specialist procedure; load that qualified skill, not a relative
cross-skill file link. Resolve current project/scene/asset IDs, expected revision,
input hashes and selected binding from actual tools. Preserve supplied provenance/
attribution facts without demanding rights clearance. Unknown or restricted rights
and absent licenses do not block production, release or packaging. Work only on declared
task-owned candidates; preserve immutable sources and approved outputs. Changes
invalidate only affected descendants. Record binding/version, job/attempt, input
and output hashes and inspected frame/sample coverage in the project.

This is independently authored guidance, not a qualified runtime route. Linux
identifies the authoring host only; adapter/platform production support is not
established. Use only advertised public actions and schemas. Missing engines,
`NOT_IMPLEMENTED`, absent actions or unsatisfied required features mean blocked:
name the operation/feature and smallest remedy, preserve existing artifacts and
return the gap. Do not fabricate media, timing, receipts or acceptance. Do not
install dependencies/models, modify configuration, upload, spend or substitute a
provider without separate authority. Optional unsupported work need not block
unrelated valid outputs. Binding changes require a revised plan, potentially new
native source, not a promise of lossless translation.

## Required and conditional capabilities

Require `scene.author@1`, `scene.render@1` with `scene.vector` and the
actual source/export format in binding constraints, `scene.frame@1` with
`timing.frame_seek`, and `inspection.playback@1` in the specified target player.
Use `inspection.visual@1` for frame comparisons and `media.probe@1` for applicable
rendered media. Export may use `delivery.encode@1` only if the selected binding
actually supports that vector format. Generic vector support does not promise
arbitrary blur, expressions or fonts in every player.

## Procedure

1. Resolve target player and version, export format, duration/rate, input vector
   provenance and feature budget. Check path animation, text shaping, masks, gradients,
   filters and looping individually against declared constraints/registered schema.
   Unknown player support is a gap, not a reason to drop an effect silently.
2. Author editable paths, text and keyframes in the supported native source format.
   Preserve source text/font dependencies and distinguish live text from approved
   outlines. Any rasterization changes editability/scalability and needs an explicit
   revised choice rather than a hidden compatibility fix.
3. Evaluate start, middle and last in-range frames, confirming geometry, labels,
   clipping and duration. Keep sample indices and source revision. A raster preview
   establishes appearance only, not the exported vector player's compatibility.
4. Export actual animation bytes with the chosen binding. Load those bytes into
   the declared player/version through an authorized playback route; inspect the
   same samples plus continuous playback, loop boundary and seek/end behavior.
   Record unsupported features and the actual player fingerprint.
5. Return editable vector source, export and player evidence with exact hashes.
   If the actual target player cannot be inspected, retain the export as an
   unqualified candidate and report playback evidence missing. Do not replace it
   with a video and claim the vector contract passed.

## Verification

**SK-S57-output (future empirical acceptance, not yet passed):** A path-and-label animation exports and plays in its declared player with matching start/mid/end frames; unsupported blur is refused or explicitly revised, not silently dropped.


## Pitfalls and handback

Report actual artifacts separately from intended outputs and unresolved gaps.
Retain failed/partial jobs and any prior approved version. Compilation, selecting
a binding, source inspection and this authoring test are not production evidence;
a newly rendered preview is an execution job. Submit only a frozen authorized
plan, reconcile uncertain effects before any retry, and use normal host approval
for typed handoffs. Return the current revisions and real artifact handles to
`motion-studio:studio-produce`; candidate encode, decode/measurement, frame/audio/
playback review and exact-byte promotion remain required when applicable. Never
turn specialist judgement into user approval or mark a route exercised from mocks.
